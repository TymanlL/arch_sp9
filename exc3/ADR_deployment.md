### **Решение**
Приведите диаграммы контекста и контейнеров в модели C4. Опишите там основные компоненты и интеграции всех элементов решения.

*Примечание: диаграммы представлены в отдельных файлах context-diagram.png и container-diagram.png*

#### Логика принятия решений:

1. **Использование существующих систем**:
   - Основой MVP является интеграция между существующим интернет-банком и АБС
   - Максимальное использование текущих возможностей систем для снижения стоимости и сроков реализации

2. **Интеграции**:
   - Между интернет-банком и АБС создается новый интеграционный компонент для обмена данными о депозитах
   - Выбор REST API для интеграций как наиболее гибкого и простого в реализации подхода
   - Асинхронный обмен сообщениями для обновления статусов заявок и уведомлений

3. **Компоненты интернет-банка**:
   - Создание нового модуля "Депозиты" в интернет-банке с функциями просмотра, оформления и отслеживания заявок
   - Разработка веб-формы заявки на депозит с валидацией на клиентской стороне
   - Интеграция с СМС-шлюзом для информирования клиентов

4. **Компоненты АБС**:
   - Доработка существующих процедур PL/SQL для приема и обработки заявок на депозит из интернет-банка
   - Разработка интерфейса для сотрудников бэк-офиса для работы с заявками из интернет-банка
   - Создание очереди заявок с приоритезацией

5. **Безопасность**:
   - Все интеграции между системами осуществляются по защищенным каналам
   - Аутентификация API-запросов через токены
   - Журналирование всех операций для аудита

6. **Модернизация сайта**:
   - Создание формы заявки на депозит на сайте
   - Интеграция сайта с АБС через API для передачи заявок
   - Интеграция с системой кол-центра для отслеживания заявок

### **Альтернативы**
Опишите здесь наиболее важные альтернативные решения.

1. **Разработка полностью автоматического процесса открытия депозитов без участия бэк-офиса сразу в MVP**
   - Преимущества: соответствие финальной цели проекта, отсутствие необходимости переделок в будущем
   - Недостатки: значительно больший объем работ, длительные сроки реализации, возможные ошибки из-за отсутствия проверки человеком

2. **Создание микросервисной архитектуры для новой функциональности**
   - Преимущества: гибкость, масштабируемость, изоляция новой функциональности от существующего монолита
   - Недостатки: сложность реализации, необходимость новых компетенций в команде, увеличение стоимости проекта

3. **Прямая интеграция сайта с интернет-банком вместо АБС**
   - Преимущества: упрощение архитектуры, единая точка интеграции с АБС
   - Недостатки: рост нагрузки на интернет-банк, усложнение процесса обработки заявок от неавторизованных пользователей

4. **Использование очередей сообщений (RabbitMQ, Kafka) для всех интеграций**
   - Преимущества: высокая надежность, асинхронность, лучшая масштабируемость
   - Недостатки: отсутствие опыта работы с технологией у команды, дополнительные затраты на инфраструктуру и поддержку

### **Недостатки, ограничения, риски**
Подробно опишите здесь недостатки, ограничения и риски выбранного решения.

1. **Технологические ограничения**:
   - Ограничения интернет-банка как монолита на устаревшем стеке (.NET Framework 4.5)
   - Необходимость работы с легаси-кодом АБС на PL/SQL
   - Ограниченные возможности масштабирования существующих систем

2. **Риски интеграции**:
   - Риск потери данных при передаче заявок между системами
   - Возможные задержки в обработке заявок при высокой нагрузке
   - Сложность обеспечения консистентности данных между системами

3. **Операционные риски**:
   - Недостаточный опыт команды в реализации подобных проектов
   - Возможное сопротивление изменениям со стороны сотрудников бэк-офиса
   - Необходимость переобучения сотрудников для работы с новым процессом

4. **Архитектурные недостатки**:
   - Решение содержит временные компоненты, которые будут заменены в полной версии
   - Ручная обработка заявок может создавать задержки и ошибки
   - Отсутствие автоматических проверок клиентских данных в MVP

5. **Риски безопасности**:
   - Увеличение площади атаки за счет новых интеграций
   - Риск несанкционированного доступа к данным о депозитах
   - Возможные уязвимости в API-интерфейсах

6. **Ограничения MVP**:
   - Отсутствие полной автоматизации открытия депозитов в MVP
   - Ограниченный функционал по управлению депозитом после открытия
   - Отсутствие интеграции с внешними системами оценки клиентов
